# 🎨 SORO | 학생 연간 이벤트 공모전 포털 (Students Annual Contest Portal)

> **상상력을 현실로!**  
> SORO는 학생들을 위해 매달 새롭게 열리는 **6대 연간 창의 공모전 및 이벤트 접수 포털**입니다.  
> 복잡한 프레임워크나 빌드 과정 없이 **HTML5, Vanilla JavaScript, CSS3** 로만 만들어졌고, 백엔드는 **Firebase**(인증·Firestore·Storage)를 씁니다.
>
> 처음에는 Google Sheets + Apps Script 로 만들었지만, 한 학급이 동시에 접속하면 로그인에 1분 넘게 걸리는 문제가 있었습니다. Apps Script 가 소유자 계정에서 요청을 하나씩 처리하기 때문이며, 코드 최적화로는 넘을 수 없는 한계였습니다(실측: 25명 동시 접속 시 최악 64초). 2026년 8월 Firebase 로 옮겼습니다.

## 🌟 핵심 기능 (Key Features)

### 1. 프리미엄 UI & 감각적인 디자인 시스템
- **다크/라이트 테마 (Theme Switcher)**: 사용자 기호에 맞춰 부드러운 전환 인터랙션과 함께 테마를 변경할 수 있습니다.
- **Glassmorphism & 조명 효과**: 트렌디한 반투명 유리 질감 효과와 마우스 커서의 움직임을 추적해 광원이 흐르는 다이내믹 카드 조명 애니메이션(`Radial Gradient Hover`)이 적용되어 있습니다.
- **아날로그 노이즈 텍스처**: 배경에 고급스러운 미세 입자 노이즈가 오버레이되어 깊이감 있고 세련된 시각적 만족감을 제공합니다.

### 2. 연간 6대 다이내믹 공모전 라인업
각 공모전의 접수 상태는 **관리자가 직접 열고 닫습니다.** 날짜로 자동 개폐하지 않는 것은 의도된 운영 방식입니다 — 자동으로 열리고 닫히면 실제 운영에서 여러 문제가 있었습니다.

| 공모전 | ID | 내용 |
| :--- | :--- | :--- |
| 키링 공모전 🎨 | `keyring` | 아크릴 키링 도안 이미지 |
| 안전 사고 예방 컷툰 📖 | `cuttoon` | 4컷 만화 원고 |
| 온라인 도서관 📚 | `library` | 책 제목·저자와 독서 엽서(캘리그라피) |
| 디지털 필사 ✍️ | `transcription` | 손글씨 이미지 또는 직접 타이핑 |
| 픽셀아트 👾 | `pixelart` | 도트 그래픽 (내장 에디터 제공) |
| 소로 사운드 앨범 🎵 | `sound_album` | 음원 업로드 |
| Zep quiz 🕹️ | `zepquiz_1`~`_6` | 회차제. 잠금이 아니라 **"접수 중인 회차"** 하나로 관리합니다 |

**젭퀴즈만 구조가 다릅니다.** 다른 공모전은 `contest_lock_<ID>` 로 열고 닫지만, 젭퀴즈는 `zepquiz_active_round` 에 적힌 회차 하나만 접수를 받습니다. 전부 닫으려면 존재하지 않는 회차인 `0` 을 지정합니다(관리자 화면의 🔒 젭퀴즈 잠금 버튼).

### 3. 시간 여행 테스트 도구 (Simulated Calendar)
- 화면 최하단에 테스트 전용 **가상 달력(Month Selector)** 바가 탑재되어 있어 클릭 한 번으로 현재 월(5월~12월)을 즉각 전환할 수 있습니다.
- 날짜 전환에 따라 공모전 카드가 활성화되거나 마감되는 로직, 폼 필드가 권한에 맞춰 반응하는 모습을 실시간으로 간편하게 검증할 수 있습니다.

### 4. 백엔드 — Firebase (되돌릴 길을 남겨 둔 채로)
- **기본값은 Firebase 입니다.** 인증은 Firebase Auth, 데이터는 Firestore, 학생 작품 파일은 Firebase Storage 에 저장됩니다.
- **되돌리기**: 주소에 `?backend=sheets` 를 붙이면 예전 Apps Script 백엔드로 그 탭에서만 전환됩니다. 이전 직후 문제가 생겼을 때를 대비해 남겨 둔 길이며, 평소에 쓸 일은 없습니다.
- **권한은 데이터베이스가 강제합니다.** 예전에는 관리자 여부를 클라이언트 코드가 판단해서, 브라우저에서 값을 조작하면 통과할 수 있었습니다. 지금은 Firestore 보안 규칙(`migration/firestore.rules`)이 직접 막습니다.
- **비밀번호 초기화**만 Apps Script 를 씁니다. 비밀번호 변경에는 브라우저에 없는 관리자 권한이 필요하기 때문입니다.

### 5. 똑똑한 작품 응모 & 실시간 취소 기능
- 로그인한 학생의 학적 정보(학년, 반, 번호, 이름)를 자동으로 연동하여 폼 입력을 최소화합니다.
- 공모전 성격에 맞는 폼 필드가 동적으로 렌더링됩니다(파일 드래그 앤 드롭 존, 멀티 텍스트박스, 탭 형태의 토글 입력 등).
- **내 접수 내역** 서랍(Drawer)을 통해 본인이 응모한 작품의 상세 내역과 제출 이미지를 즉각 조회하고, 필요 시 안전한 절차를 통해 응모를 취소(데이터 영구 삭제)할 수 있습니다.

## 🔧 운영하면서 알아야 할 것

### app.js 뒷부분의 Apps Script 코드는 자동 반영되지 않습니다
`app.js` 파일 뒤쪽에 주석으로 들어 있는 Apps Script 코드는 **문서용 사본**입니다. 여기를 고치고 배포해도 실제 서버 동작은 그대로입니다. 반드시 **구글 시트 → 확장 프로그램 → Apps Script** 에 붙여넣고, **배포 → 배포 관리 → 편집(연필) → 새 버전 → 배포** 를 해야 반영됩니다.

> ⚠️ **"새 배포" 가 아니라 기존 배포의 "새 버전"** 이어야 합니다. 새 배포를 만들면 주소가 바뀌어 사이트가 백엔드를 찾지 못합니다.

### 관리자 권한은 Firestore 문서에 있습니다
`users/{uid}` 문서의 `admin` 이 `true`(boolean) 여야 관리자로 인정됩니다. 학번을 비교하던 예전 방식은 브라우저에서 조작할 수 있어 바꿨습니다.

**보안 규칙이 "본인이 자기 문서에 admin 을 붙이는 것" 을 막습니다.** 학생이 스스로 관리자가 되는 걸 막는 장치인데, 선생님에게도 똑같이 적용됩니다. 그래서 처음 한 번은 **Firebase 콘솔에서 직접** 넣어야 합니다(Firestore → `users` → 해당 문서 → 필드 추가 → `admin` / `boolean` / `true`). 넣은 뒤 **로그아웃 후 다시 로그인**해야 반영됩니다 — 관리자 토큰은 로그인할 때 발급됩니다.

### 비밀번호 초기화에는 승인이 없습니다
학생이 학년/반/번호/이름을 입력하면 **즉시** 임시 비밀번호(`a1234567!`)로 바뀌고, 그 비밀번호로 로그인하면 새 비밀번호를 직접 정합니다. 선생님이 할 일은 없습니다.

**대신 알아두실 점:** 초기화에 필요한 정보는 갤러리에 그대로 보이고 임시 비밀번호도 고정값이라, 마음먹으면 **남의 계정을 초기화하고 그 계정으로 로그인할 수 있습니다.** 승인 단계를 없앤 대가이며 코드로 막을 수 없습니다. 그래서 다음을 두었습니다.

- 관리자 계정은 이 경로로 초기화할 수 없습니다
- 같은 계정은 1분에 한 번, 전체로는 시간당 30건까지
- **모든 초기화가 기록으로 남습니다** — 관리자 화면 "비밀번호 초기화 기록"

**모르는 이름이 그 목록에 올라오면 누군가 남의 계정을 건드린 것**이니 살펴봐 주세요. 이 기록이 승인을 대신하는 유일한 안전장치입니다.

### 학생 작품 파일은 Storage 에 있습니다
그림과 음원은 Firebase Storage 에 올리고, Firestore 문서에는 **주소만** 저장합니다. 경로는 `submissions/<공모전ID>/<학생uid>/<항목>.<확장자>` 로 고정되어 있어 다시 제출하면 같은 자리를 덮어씁니다.

> 이전 초기에는 이 단계가 빠져 base64 를 문서에 통째로 넣었고, 엽서 한 장(0.89~1.13MB)이 Firestore 문서 한도(1MiB)를 넘어 **저장이 통째로 실패했습니다.** 게다가 오류 문구가 "현재 접수 기간이 아닌 공모전입니다" 로 나와 학생은 원인을 알 수 없었습니다. 지금은 실패 원인을 구분해 알리고, 파일 업로드가 실패하면 저장을 진행하지 않습니다.

### 캘리그라피 엽서 배경 (`asset/backgrounds/`)

온라인 도서관의 엽서 배경입니다. 학생이 테마를 고르면 그 안에서 무작위로 한 장이 뽑히고, 그릴 때마다 색감이 다르게 입혀집니다.

**새 배경을 추가할 때: 4:3 가로, 1200×900 이상.** 엽서 캔버스가 800×600이라 세로 사진을 넣으면 가운데만 잘려 보입니다.

파일을 넣은 뒤 `app.js` 의 `CALLIGRAPHY_THEMES_IMAGES` 목록에 경로를 추가해야 실제로 쓰입니다.

> ⚠️ **파일 이름의 앞부분은 테마를 뜻하지 않습니다.** 테마가 잘못 붙어 있던 사진들을 맞는 테마로 옮겼기 때문에, 예를 들어 `forest` 목록에 `sky_1.jpg`(잎사귀 사진)가 들어 있습니다. 이름을 바꾸면 변경 기록을 따라가기 어려워져 그대로 두었습니다.

> ⚠️ **목록에 없는 파일도 폴더에는 남아 있습니다.** 중복이거나 테마와 무관한 사진(게임 컨트롤러, 서류가방 든 사람 등)을 목록에서만 뺐습니다. 지우지 않은 것은 나중에 판단이 바뀔 수 있어서입니다.

**배경 종류:** 2026년 9월 기준 하늘·숲·바다·공간·종이/추상 테마별로 30장씩, **총 150장**입니다. 같은 사진이 뽑혀도 결과가 서로 달라 보이도록 그릴 때마다 색조·채도·밝기를 조금씩 바꾸고, 여섯 가지 색감 중 하나를 덧입히고, 절반은 좌우를 뒤집고, 가장자리 어둡기를 무작위로 줍니다.

### 배포 후 학생 화면이 안 바뀌면
`index.html` 의 `?v=` 값을 올려야 브라우저가 새 파일을 받습니다. 관리자 화면을 열어 둔 채 배포하면 옛 코드가 계속 돌므로, **강력 새로고침**(윈도우 `Ctrl+Shift+R`, 맥 `Cmd+Shift+R`)이 필요합니다.

## 🌐 Vercel 호스팅 배포 방법
본 프로젝트는 `vercel.json` 파일이 사전 최적화되어 있으므로 별도의 빌드 커맨드 설정 없이 즉시 배포할 수 있습니다.

1. [Vercel](https://vercel.com)에 가입 후 로그인합니다.
2. **[Add New] -> [Project]**를 선택하여 이 프로젝트가 올라가 있는 Github 저장소를 불러옵니다.
3. 빌드 및 설정 구성(Build and Development Settings)은 수정할 필요 없이 **[Deploy]** 버튼을 클릭합니다.
4. 배포가 1분 이내에 완료되며, 세계 어디서나 접속할 수 있는 `.vercel.app` 고유 주소가 생성됩니다!
