# 2단계: Firestore 구조와 보안 규칙

시트 4장을 Firestore 컬렉션 4개로 옮기는 설계입니다.
규칙 본문은 [`firestore.rules`](firestore.rules)에 있고, 이 문서는 **왜 그렇게 했는지**를 적습니다.

---

## 컬렉션

### `users/{uid}`

문서 ID는 Firebase Auth의 uid입니다. **비밀번호는 여기 없습니다** — Auth가 관리합니다.

| 필드 | 예시 | 비고 |
|---|---|---|
| `grade` `classNum` `number` | `5` `1` `27` | 숫자 |
| `name` | `"김태호"` | |
| `userKey` | `"5_1_27_김태호"` | 이전 데이터와 대조용. 새 코드는 uid를 씁니다 |

기존 `Password` 열은 옮기지 않습니다(1단계에서 Auth로 가져오는 게 확인됨).

### `submissions/{contestId}__{uid}`

**문서 ID를 고정한 것이 이번 설계의 핵심 변경입니다.**

| 필드 | 비고 |
|---|---|
| `uid` | 소유자. 규칙이 이 값으로 권한을 판단합니다 |
| `contestId` `contestTitle` | |
| `studentName` `studentGrade` `studentClass` `studentNumber` | 갤러리 표시용으로 복사해 둠 |
| `timestamp` | |
| `data` | 작품 내용. **시트에서는 JSON 문자열이었지만 이제 그냥 중첩 필드입니다** |
| `isStarred` `prizeStatus` `award` | 관리자 전용. 학생은 쓸 수 없습니다 |

ID를 `contestId__uid`로 정하면 세 가지가 공짜로 따라옵니다.

1. **한 학생이 한 공모전에 하나만** — 지금은 읽을 때 중복 제거로 처리하는 걸 DB가 보장합니다.
2. **재제출해도 반응이 살아남습니다** — 지금은 취소 후 다시 내면 id가 바뀌어 받은 반응이 사라집니다. 같은 문서를 덮어쓰면 그 문제가 없어집니다.
3. **내 제출물 조회가 질의 없이 됩니다** — `contestId__uid`로 바로 문서를 집으면 됩니다.

### `reactions/{submissionId}__{uid}__{type}`

| 필드 | 비고 |
|---|---|
| `submissionId` `uid` `type` | `type`은 `read` · `art` · `heart` |
| `createdAt` | |

ID를 이렇게 조합하면 **같은 사람이 같은 작품에 같은 반응을 두 번 남기는 게 구조적으로 불가능**합니다.
지금은 서버가 기존 행을 찾아 지우는 방식으로 처리하고 있습니다.

### `settings/{key}`

`contest_lock_library`, `zepquiz_active_round`, `zep_prize_...`, `zep_student_count_...` — 키 이름은 지금 시트와 똑같이 씁니다.
값은 `{ value: ... }` 한 필드에 담습니다.

## 규칙이 실제로 막는 것

| | 지금 (Apps Script) | 규칙 적용 후 |
|---|---|---|
| **남의 이름으로 제출** | ❌ 못 막음. Users 시트에 그 조합이 있는지만 확인 가능해서, 갤러리에 노출된 학년·반·이름을 베껴 보내면 통과 | ✅ `request.auth.uid`가 아니면 문서 자체를 못 씀 |
| **남의 작품 삭제** | 소유자 대조로 막음 (직접 넣은 검증) | ✅ DB가 강제 |
| **마감된 공모전 제출** | 서버 코드로 검사 | ✅ 규칙이 `settings`를 읽어 판단 |
| **학생이 수상/사은품 표시 조작** | 검사 없음 — 보내면 그대로 저장됨 | ✅ 해당 필드를 학생이 못 씀 |
| **자기 작품에 반응** | 막지 않음 | ✅ 차단 |
| **관리자 판별** | 학년·반·번호·이름 값 비교(위조 가능) + 서버 토큰 | ✅ Auth 커스텀 클레임 |

관리자 지정은 코드가 아니라 **커스텀 클레임**으로 바뀝니다. 하드코딩된 `5_1_27_김태호`가 사라지고,
담당자가 바뀌어도 코드 수정 없이 클레임만 옮기면 됩니다.

## 아직 정하지 않은 것

### 제출물 공개 읽기 — 학생 이름이 그대로 노출됩니다

갤러리와 전자화랑이 **로그인 없이** 보여야 해서 `submissions` 읽기를 공개로 뒀습니다.
그런데 Firestore 규칙은 "이 필드만 빼고 보여주기"가 안 됩니다. 즉 주소만 알면 전체 이름을 볼 수 있습니다.

**이건 지금 Apps Script 구조와 똑같은 수준입니다** — 현재도 `getAllSubmissions`가 전체 이름을 그대로 돌려줍니다.
그래서 이번 이전으로 나빠지는 건 없지만, 좋아지지도 않습니다.

더 가리려면 **공개용 사본 컬렉션**(이름을 미리 마스킹해 저장)을 따로 둬야 하고, 쓰기가 두 곳으로 늘어납니다.
지금 결정하지 않고 **4단계에서 실제 화면을 보며 판단**하는 게 낫다고 봅니다.

## 질의 패턴과 색인

[`firestore.indexes.json`](firestore.indexes.json)에 세 개를 넣어뒀습니다.

| 쓰이는 곳 | 질의 |
|---|---|
| 갤러리·전자화랑 | `contestId` 일치 + `timestamp` 내림차순 |
| 학년 필터 | `contestId` + `studentGrade` + `timestamp` |
| 반응 집계 | `submissionId` + `type` |

학년 필터는 지금처럼 **받아온 뒤 클라이언트에서 걸러도** 됩니다(작품 수가 적음).
그 경우 두 번째 색인은 필요 없어지지만, 넣어둬도 비용은 없습니다.
