# Firebase 이전 — 1단계: 비밀번호 이전 검증

> ## ✅ 검증 완료 (2026-08-22)
>
> **기존 비밀번호를 그대로 옮길 수 있습니다.** 전원 재설정은 필요 없습니다.
>
> 시험 계정을 우리 SHA-256 해시로 가져온 뒤 원래 비밀번호로 로그인한 결과
> `registered: true` 와 함께 정상적으로 토큰이 발급됐습니다.
>
> **확정된 명령 조합** (3단계에서 실제 학생 계정을 옮길 때도 이대로 씁니다):
>
> ```
> --hash-algo=SHA256  --rounds=1  --hash-input-order=PASSWORD_FIRST
> ```
> 그리고 `salt` 필드는 **넣지 않습니다**. `passwordHash`는 표준 base64입니다.
>
> 처음 실패했던 원인은 **`--hash-input-order` 누락**이었습니다. 이 플래그가 없으면
> 업로드는 성공해도(`Imported successfully`) 로그인은 실패합니다.

이 폴더는 **Apps Script → Firebase 이전 계획의 1단계** 도구입니다.

## 왜 이걸 먼저 하나

학생 비밀번호가 지금 **솔트 없는 SHA-256(소문자 16진수)** 으로 Users 시트에 저장돼 있습니다.
Firebase Auth는 기존 해시를 가져오는 기능을 제공하지만, **우리 방식이 그대로 통하는지는 실제로 해봐야 압니다.**

- **통하면**: 학생 300명이 지금 쓰던 비밀번호를 그대로 씁니다.
- **안 통하면**: 전원이 비밀번호를 새로 설정해야 합니다 — 운영 부담이 크고 일정이 달라집니다.

그래서 **다른 걸 만들기 전에 이것부터** 확인합니다. 나중에 발견하면 최악입니다.

## 안전한가

네. **실제 학생 데이터를 전혀 쓰지 않습니다.**

- 비밀번호를 아는 **가짜 계정 1개**로만 시험합니다
- 기존 스프레드시트·Apps Script·라이브 사이트를 건드리지 않습니다
- 실패해도 되돌릴 게 없습니다 (시험용 Firebase 프로젝트만 지우면 끝)

## 실행 순서

### 1. Firebase 프로젝트 만들기 (시험용)

<https://console.firebase.google.com> 에서 새 프로젝트를 만듭니다.
이름은 아무거나 (예: `soro-migration-test`). **결제 계정 등록 불필요** — Auth는 무료 한도로 충분합니다.

만든 뒤 **빌드 → Authentication → 시작하기 → 이메일/비밀번호 사용 설정**을 켭니다.

### 2. Firebase 로그인

CLI는 **설치 없이 `npx`로** 씁니다 (전역 설치는 관리자 권한이 필요해서 막힙니다).

```bash
npx --yes firebase-tools@latest login
```

브라우저가 열리면 **구글 계정으로 로그인**합니다.
이 단계는 계정 인증이라 **반드시 본인이 직접** 해야 합니다.

### 3. 가져오기 파일 생성

```bash
node make-import-file.js --test > test-users.json
```

화면에 시험 계정의 **로그인 이메일과 비밀번호**가 출력됩니다. 메모해 두세요.

### 4. Firebase에 가져오기

`<프로젝트ID>` 를 1번에서 만든 프로젝트 ID로 바꿔서 실행합니다.

```bash
npx --yes firebase-tools@latest auth:import test-users.json \
  --hash-algo=SHA256 \
  --rounds=1 \
  --hash-input-order=PASSWORD_FIRST \
  --project <프로젝트ID>
```

`Processed 1 user` 같은 메시지가 나오면 업로드는 성공입니다.
**단, 이건 "파일을 받았다"는 뜻이지 "비밀번호가 맞다"는 뜻이 아닙니다.** 5번이 진짜 검증입니다.

> **`--hash-input-order` 를 빠뜨리지 마세요.** SHA 계열은 해시를 `SHA(비밀번호+솔트)`로 볼지
> `SHA(솔트+비밀번호)`로 볼지 이 플래그로 정합니다. 지정하지 않으면 로그인이 실패할 수 있습니다.
> 우리는 솔트를 쓰지 않아 둘 중 어느 쪽이든 결과가 같지만, 플래그 자체는 넣어야 합니다.

### 5. 실제로 로그인되는지 확인 ← **이게 핵심**

Firebase 콘솔 → **프로젝트 설정 → 내 앱 → 웹 앱 추가**로 설정값(`firebaseConfig`)을 얻은 뒤,
`login-test.html` 파일 상단의 설정 부분에 붙여넣고 브라우저로 엽니다.

3번에서 받은 이메일과 비밀번호로 로그인해 봅니다.

- **로그인 성공** → 기존 비밀번호를 그대로 옮길 수 있습니다. 2단계로 진행.
- **로그인 실패** → 해시 형식이 맞지 않습니다. `--rounds` 값을 바꿔 재시도해 보고,
  그래도 안 되면 **전원 비밀번호 재설정**을 전제로 계획을 수정해야 합니다.

## 통과한 뒤에 할 일

실제 학생 계정을 옮길 때는 같은 스크립트에 시트에서 뽑은 값을 넘깁니다:

```bash
node make-import-file.js "5_1_27_김태호" "<그 학생의 해시>" "5_1_20_조하린" "<해시>" ... > users.json
```

다만 **실제 이전은 도서관 공모전이 끝난 10월 이후**에 하기로 했습니다.

## 참고: 합성 이메일

학생은 학년/반/번호/이름으로 로그인하지 이메일을 쓰지 않습니다.
Firebase Auth가 이메일을 요구하므로, `userKey`를 해시한 ASCII 주소를 만들어 씁니다.

```
5_1_27_김태호  →  u30ec1130...@soro.local
```

이름에 한글이 들어가면 이메일 주소로 쓸 수 없어서 이렇게 합니다.
학생은 이 주소를 볼 일이 없고, 앱이 로그인할 때 같은 규칙으로 다시 만들어 씁니다.
이름·학년·반·번호는 Firestore 프로필에 그대로 저장합니다.
